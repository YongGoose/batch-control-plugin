The Jenkins permissions to grant temporarily on the one job or folder named above, and on no other item.
  • Configure: change the item's own configuration. For a folder, that is the folder's settings: the window gives no permission on the items inside the folder, but the folder's settings still affect them (for example implicitly loaded Pipeline libraries), and reconfiguring a Multibranch Pipeline or organization folder can create or delete the items it generates.
  • Create: create new items directly inside the folder. Applies only to a regular folder. While Create is ticked, the optional New job name restriction limits which new job the window lets you create:
    • An exact item name, for example nightly-report: only a job with exactly that name can be created.
    • A Java regular expression between slashes, for example /report-[0-9]+/: the expression must match the whole item name (the name of the new job itself, not its folder path).
    Leave it empty to allow any name in the folder. The restriction is checked when you submit (an invalid expression is refused) and shown to the approver. It does not affect Configure or Delete. An attempt to create a job with another name is refused and recorded as a grant violation.
  • Delete: delete the job. Applies only to a job.
A request for Create or Delete on an item where it does not apply is refused when you submit it. No window allows renaming a job or folder of any kind: neither a Configure window nor Delete and Create windows together. A rename needs an administrator, or your own standing permissions: Configure on the item, or Delete on it plus Create in its parent (the folder that contains it, or Jenkins itself for a top-level item). A window applies only to the item it was approved for. It follows that item when an administrator (or a user with their own permissions) renames or moves it, and ends when the item is deleted.
