When enabled, Batch Control watches changes to jobs:
  • job creation, configuration, deletion, rename and move are recorded in the change history, with a diff of config.xml for configuration changes (this recording is also enabled by Enable run control);
  • deleting a job is refused unless the user holds an active permission window that covers it;
  • an administrative monitor reports accounts that hold standing Create, Configure or Delete permissions outside the permission-window flow;
  • each job's sidebar offers Request Change Permission, which opens the grant screen with that job filled in.

This switch does not decide whether creating or configuring a job needs a permission window. That is decided by the authorization strategy: select Batch Control (wrapping) in Configure Global Security and it grants time-limited Item Create, Configure and Delete permissions from approved windows. Without that strategy, an approved window confers nothing.

Because permission windows live in the authorization strategy rather than in this switch, requesting and approving a window still works while this switch is off, and turning it off does not revoke windows that are already active. Turning it off does stop the delete veto and the administrative monitor.
