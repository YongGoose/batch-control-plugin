## Defects

**DEF-01 (low-medium, #89 not fully met): short cells in the grants tables still wrap at 1280 px.**
Steps: 1280x900 viewport; one active and one ended window present (any approved grant, one revoked);
open `/jenkins/batch-control/grants/` as admin and as the window holder (mover1).
Expected: IDs, statuses, approver names and the How column stay on one line, no horizontal scroll.
Actual (`89-04-admin-grants-1280`, `89-04-mover1-grants-1280`):
- Grant Requests (admin): "approver-2" breaks as "approver-" / "2".
- Active Grants (admin): header "New job names" on 3 lines, value "any name" on 2 lines.
- Ended Grants: "Revoked by admin" on 2 lines (admin) and on 3 lines next to "Request again" (mover1); header "New job names" on 2-3 lines.
- mover1's page scrolls horizontally (scrollWidth 1291 > 1280); the Grant Requests status cell "window open, 58 min left" reaches the edge.
Owner: `src/main/resources/io/jenkins/plugins/batchcontrol/action/GrantsSection/index.jelly`,
`.../ActiveGrantsSection/**` (ui-dev): `white-space: nowrap` on the ID, user/approver, actions and How
cells, a shorter header ("Names"), or letting Reason/Scope take the wrapping.

**DEF-02 (low, #86): the monitor link still reads "Change Records".** Monitor text: "Check what was changed
under the permission window (see Change Records, the Changes tab of Batch Control) ...". The issue asked
for the label to match the tab. Owner: `src/main/resources/io/jenkins/plugins/batchcontrol/ops/BatchControlStrategyMonitor/message.jelly:112` (ui-dev).

**DEF-03 (low, #86): the "Marked as reviewed" page's breadcrumb names the wrong concern.** Breadcrumb:
"Batch Control: grants need a Batch Control authorization strategy › ..." (`86-04-reviewed-page-header`),
which is the monitor's display name, while the page is about an item changed under a window and the
strategy is fine. Owner: `src/main/resources/io/jenkins/plugins/batchcontrol/Messages.properties:12`
(`BatchControlStrategyMonitor.DisplayName`, for example "Batch Control: authorization strategy and
changed items") or a page title in `.../ops/BatchControlStrategyMonitor/reviewed.jelly` (ui-dev).

## UX observations (for human judgement)

1. #83: the Move page itself shows no hint that a destination listed only because of a Create window
   still needs Delete on the source (`83-01`). The refusal page explains it well and has the links.
2. #84: the Changes table's single Grant column for a MOVE shows only the Create grant. The detail text
   names both windows.
3. #75: after the requester gains Build, other viewers keep seeing the notice for up to 5 minutes unless
   the request changes. This is the documented cache. Re-designating clears it at once.
4. #72: core still renders an empty "Legacy" card under the "Batch Control" card on a job without builds
   (core's permalinks table).
5. #87: a user holding Request only on a folder and with no request yet still gets 404 on `/batch-control/`
   (D-38b, no scan of all items). The job page's Request Run is their entry point.
6. The grant request detail says "Duration 1 minutes" (singular/plural)
   (`GrantRequestItem/index.jelly:45`). The 1-minute default is from the e2e JCasC options.
7. With change control off, the grants page shows no tables, so the revoked windows are visible only
   after it is turned back on (or in Changes).
