## Defects

**DEF-05 (low-medium, regression of #89/DEF-01 caused by D-68): the grants page scrolls horizontally at 1280 px
because the ID column holds a 36-character UUID that does not wrap.**
Steps: 1280x900. Create one or two pending grant requests and one active window (any user). Open
`/jenkins/batch-control/grants/` as admin, as an approver, or as a window holder.
Expected: no horizontal scroll (#89). Long state text may wrap.
Actual (`W-admin-grants-1280.png`, `s_width.jsonl`): scrollWidth is 1387 (admin), 1324 (approver-1), 1311 (fonly)
and 1349 (approver-1, dark). The ID cell is `white-space: nowrap` and 287-330 px wide in all three tables. The Active
table is 1265 px for admin (it adds the Revoke column), and the main panel grows past the content column. The header
button "Request Change Permission" ends at x≈1350, outside the viewport. Run Requests (5 columns) and Activations
stay at 1280.
Owner: ui-dev, `src/main/resources/io/jenkins/plugins/batchcontrol/action/GrantsSection/index.jelly` (ID cells of
the Pending, Active and Ended tables). Suggestion: show a short id (the first 8 hex digits) as the link text with the
full UUID in `title`, or let the ID cell wrap (`word-break: break-all` on the link). The same applies wherever a
UUID sits in a nowrap cell (the Run Requests and Activations ID columns fit today only because those tables are
narrower).

## UX observations (for human judgement)

1. **New job page overflow menu on a job without a completed build (third party).** With the Rebuild plugin
   installed, core's `contextMenu` returns "Rebuild Last" with `url: null` for a job that has no completed build.
   Core 2.568.3's new job page then throws `TypeError: Cannot read properties of null (reading 'startsWith')`
   and renders an empty "More actions" menu (`recon_overflow.py`). The same happens for admin with
   configuration-as-code's "Export Configuration". So on a new, never-built job, "Request Change Permission"
   cannot be reached from the new job page menu. The grants page button and the classic page still work. This is
   not a Batch Control defect, but it is the most likely first contact for "I need to configure this new job".
   Consider a line in LIMITATIONS.
2. **Console error on every job page from core's DialogEvent (D-70).** `DialogEvent.of(...)` serialises
   `javascriptUrl: "/jenkins/static/<hash>/"`, and the browser logs "Refused to execute script ... MIME type
   ('text/html')". Core's own "Build with Parameters" does the same (`param-core`, no Batch Control property).
   This is core behaviour of the Beta API and has no visible effect.
3. **Tabs wrap at 1280 px for approvers and Manage holders with badges.** Eight tabs plus three badges no longer
   fit the 1036 px content column. "History" moves alone to a second, centred row, and the whole bar switches
   from left-aligned to centred (`DK-overview.png`). Admin (no badges) stays on one row. This is acceptable, but an
   orphan tab looks accidental.
4. **Pre-ticked action in the job/folder dialogs.** The job page dialog opens with Configure ticked, the folder
   page dialog with Create ticked, and the grants page dialog with nothing ticked (`probe_tick2.py`). This is
   sensible, but a user who ticks "all three" by clicking each box un-ticks the preset one. I did exactly that on
   the first attempt and got a FOLDER_ONLY request without CREATE.
5. **Links on list pages.** Run Requests list "Job" and grants "Scope" are plain text. Activations (list and
   detail) and the request detail link the job with `model-link`. Linking them would also give the R4-11 chevron
   there.
6. **Change record ids keep the timestamp format** (`20261004-004151-hukobf` in History/CSV). D-68 covers requests
   and windows only, so this is consistent with the decision. Mentioned only so that it is not mistaken for a
   leftover.
7. **Folder description edit under a window.** A FOLDER_ONLY holder can save the folder's configure page.
   Core's inline "Edit description" on a folder posts to the folder's view and needs View/Configure, so it
   returns 403 with "missing the View/Configure permission". This is core behaviour and applies to FOLDER windows
   too.

## Requests

- Request: `src/main/resources/io/jenkins/plugins/batchcontrol/action/GrantsSection/index.jelly` (ui-dev): DEF-05,
  stop the UUID ID column from forcing horizontal scroll at 1280 px (short id + title, or allow wrapping).
- Request: `docs/LIMITATIONS.md` (release-manager): optional. On the new job page (experimental core UI), a plugin
  menu item with a null URL (e.g. Rebuild's "Rebuild Last" on a job without a completed build) breaks core's
  overflow menu, so "Request Change Permission" is reachable there only from the grants page or the classic page.
