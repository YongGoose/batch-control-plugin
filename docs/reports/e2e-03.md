**DEF-01 (High) — a refused Build on a job without parameters is a silent failure.**
Steps: requester (or admin) opens `batch-lock`, `batch-cbn`, `batch-throttle` or

and naginator's Retry on approval-required jobs. Server state correct (no build).

A row is PASS only if all five hold, each recorded separately in the checklist columns
`Roles checked | Visibility | Goal | Refusal UX | Record | Evidence`:

(3) **Refusal UX** — the user sees why and what to do next (bare "Access Denied", stack trace, generic toast, unexplained 4xx = ✗);

- U-14 A CONFIGURE window also gives the holder Rename and the Authorization page (the latter guarded, B9-01).
- U-15 The approved build shows request id/requester/approver only in the cause line; no link back to the request (ApprovedRunAction has no UI).
- U-16 The rerun request page does not link back to its incident; the rerun form has a single Approver select while run requests take several.
- U-17 TRIGGER_BLOCKED coalescing per job and cause kind: a blockUpstream refusal inside the hour is merged into an earlier
  "switch=activation" record, so the record names the wrong switch for the later refusal (B5-14).
- U-18 The self-grant guard's revert is silent: the save looks successful and the entry is gone on reopen (B9-01).
- U-19 A Job DSL change is recorded as SYSTEM with no hint of the seed job (B11-02).
- U-20 Dashboard/History forms put the crumb and a json blob into the URL (`?days=1&Jenkins-Crumb=…&json=…`).
- U-21 Branch-indexing runs are classified OTHER rather than SCM.
- U-22 Under a Thai JVM locale the dashboard renders durations in Thai digits ("๖ sec") next to ASCII dates.
- U-23 "activation is held by team-mb, which is on hold" — "held" reads as "on hold".
- U-24 In this role set nobody but an administrator can request a rerun: it needs ViewHistory (to open the incident), Request and Job/Build.
- U-25 The save-failure page (B1-20) shows the raw file path and the Java exception text.
- U-26 The New Grant Request form keeps "1 minute" as the default duration (the first option), which is easy to submit by accident.

  HOLD request stopped it (one in-flight build, none after). Seed fixed; B5-21's own result (two builds per request) stood.
- The container was stopped on purpose for 75 s (B17-04) and restarted three times (B17, B18 override profile in and out).
  A second, clean Jenkins (`bc-clean`, 1.2 GB limit) ran only for B21-01/02 and was removed.
- Screenshots: all 288 run-3 captures were re-audited (`e2e/browser/audit-shots.mjs`); 32 full-viewport or unboxed captures were
  re-cropped to their content and boxed (same pixels) or retaken; one unreferenced capture (PR-06-0) was removed.
