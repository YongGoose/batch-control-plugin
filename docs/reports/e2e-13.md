## UX observations (for human judgement)

- **U-1 (upstream Jenkins core 2.568.3, not Batch Control).** This happened intermittently: once in the evidence run, 5 of 6 repro tries, 0 of 7 in two other tries,
  after the admin revoke on `/batch-control/grants/`. The page error was `TypeError: Cannot read properties of undefined
  (reading 'replace') at xmlEscape (header.js:37) at menuItem (header.js:173) … generateDropdownItems`.
  The cause is core's breadcrumb overflow menu (`computeOverflow` in `jsbundles/header.js`). It maps hidden
  breadcrumbs to `{label: …}`, but `menuItem` reads `displayName`, so the overflow dropdown throws
  whenever `#breadcrumbBar` overflows at load. The page works and nothing visible breaks. It is
  timing-dependent, I could not reproduce it by hovering, and it is unrelated to role-strategy. Owner: none (an
  upstream core issue could be filed). It is a different bug from the `rebuild` "Rebuild Last" null-URL one in e2e/README.
- **U-2 (role-strategy 927 UX).** For an invalid pattern, the message `Unclosed group near index 5<br>team(`
  shows in the dialog as "…index 5team(", because the line break is lost. role-strategy's own
  descriptor returns the same body (R13-6), so this is role-strategy's rendering.
- **U-3 (role-strategy 927 UX).** An unknown user or group gets no worded warning. It is only struck through, with a
  tooltip ("User not found"), and Add stays enabled, so an admin can assign a role to a typo.
  role-strategy behaves the same. We used to flag padded sids ourselves (`doCheckForWhitespace`). Now a padded sid
  resolves silently, and the dialog trims it before saving, so nothing bad is stored.
- **U-4.** A valid pattern gets no positive feedback, such as a list of matching items, on blur. role-strategy 927 has a
  matching-items list in its bundle, but it did not appear in the add dialog in this run.
- **U-5.** To drop a user's last item role you cannot untick it, because Save is disabled with zero roles. You have to use "Remove user",
  whose confirmation reads "Remove "nobc" and all its role assignments?" even though it only acts on
  the current tab's role type. That wording is role-strategy's.
- **U-6 (Playwright only).** Clicking the already selected tab on the role pages is intercepted by
  the tablist container. Unselected tabs click normally. A human does not notice this.
