  GET, and "Scan Multibranch Pipeline Now" (`build?delay=0`) answers 405 to a GET, because it is POST-only. Workspace answers 404 before
  the first build. Same as e2e-12 Known 4.
- On never-built freestyle `batch-daily` with `rebuild` enabled, the new job page More actions menu does not open
  ("Jumplist request failed: TypeError ... reading 'startsWith'", rebuild's null-URL "Rebuild Last"). This is e2e-12
  Known 2, and it happens identically on the job page `/job/batch-daily/`. With `rebuild` disabled (`rebuild.jpi.disabled`,
  e2e/README e2e-06 note) the menu opens and matches (R1).

  ('text/html') ..." on the core job page `/job/<job>/` itself as well as on its sub-pages (`probe.jsonl`). This is e2e-11 UX 2.

## Documentation defects

- `e2e/init.groovy.d/20-sample-jobs.groovy` (mine, fixed in this commit): the seeded `team-mb` GitSCMSource had no
  traits, so "Scan Multibranch Pipeline Now" discovered **no branches** ("Finished branch indexing" with no children). The
  multibranch pages of earlier rounds therefore had no branch jobs. The seed now adds `BranchDiscoveryTrait` (what the
  configure page adds by default). I verified this on a fresh home: indexing created `feature-1` and `main`, and there was 0 SEVERE.
  `r15/arrange.py` adds the trait to homes seeded earlier.
- None in the project README for this scope (nothing about multibranch activation was followed from it in this run).

## UX observations (for human judgement)

1. On a branch job's activation page, the sentence "Make activation or hold requests on the folder that carries it."
   names `team-mb` but does not link to `/job/team-mb/batch-control-activation/`. The user has to go up through the
   breadcrumb and find the activation notice on the folder page. A link would save two clicks.
2. The folder side panel's Request Change Permission href is written as
   `/jenkins/job/team-mb/../../batch-control/grants/new?scopeFullName=team-mb`. It resolves correctly (200, and the click
   opens the dialog), but the `..` segments show in the status bar on hover. The same href is on the folder's own
   page, so this is not specific to the activation page.
3. For a new-job-page user the computed-folder activation page keeps the classic layout, including the Build Queue
   and Executors widgets, while the job activation pages next to it do not. That is consistent with the folder's own page,
   since folders have no new job page, and it is working as designed per the comment in `JobActivationForm/index.jelly`.
